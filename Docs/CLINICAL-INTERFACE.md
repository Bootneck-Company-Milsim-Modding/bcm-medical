# Clinical interface development

The panel follows the company concept supplied on 26 October: compact native-styled tab bar, supplied Bootneck Company logo, status/treatments left, supplied anatomy in the centre and named patient choices right. The body JPG is converted to PNG only for engine import; the logo and illustration are preserved. Native Workbench builds the two EDDS resources. Source provenance: user-provided BC Logo.png, a-man-s-body-outline-in-black-and-white-vector.jpg and MEDIAL INTERFACE.jpg. Rights review of supplied artwork remains a release-packaging task.

Seven actual click targets map the figure to head, chest, abdomen, patient's left/right arms and patient's left/right legs. Patient-left is on the viewer's right. The first open and a body selection alone reveal no findings. Region checks are timed using the saved examination control and return only to the requesting player. Every reply carries patient identity and panel view generation; changing patient or reopening prevents stale results populating a new chart. Findings are retained per region/check only for the current panel view. Supply counts come from the acting character's server inventory.

Bleeding, airway, breathing, pulse/rate and blood-loss checks expose qualitative findings. Instrumented exact measurements are not implemented by a bare-hands check. Pain and Medication provide private timed assessments and records, followed by finite-supply medication actions. Clicking a region shows relevant checks; after checking bleeding it also offers applicable kit treatments. Surgery requests carry the selected region so they cannot silently operate on another body part. Self/Swap and paged patient buttons select self, accessible nearby living characters within the saved treatment range, a directly looked-at living casualty or occupants of the same vehicle, with server permission checks. Viewing is separate from permission to treat inside a seat.

Bandaging uses the native dressing item: equip gadget, play the selected self/other/revive animation and let native completion apply the selected hit-zone effect and consume the original item. BCM does not create a visual animation while separately applying an instant heal. Separate surgery/suture/splint operations now use native treatment-loop placeholders with a no-heal presentation effect. Native completion and the authority timer gate original inventory consumption; owner-only countdown and cancellation are retained. Medication uses the native injection graph with the same authority protocol. New bandage application duration is saved in GM > BCM Medical | Bleeding (default 10 seconds). Current catalogue: 105 controls/schema 15, with explicit validation/migration of schemas 1–14.

Current graphical acceptance includes actual native screenshot/mouse review and 720p/1080p runtime checks. Gold buttons use dark labels, anatomy has hover/selection highlights and a click hint, and the former Blood tab is labelled Fluids. Treatment applicability is an owner-only snapshot sent after a bleeding examination; healthy limbs cannot enable Bandage even when a dressing exists. Bandaging no longer closes the panel. All procedures still revalidate the actual condition, inventory and permissions on the server. New injury or completed treatment requires another examination to refresh applicable wound actions.

The patient list refreshes once a second, preserves existing row order, and appends new accessible discoveries. More Patients pages that actual list six rows at a time; it is disabled when no extra page exists. Distance and line-of-sight follow examination access, with same-vehicle viewing retained. It does not search the whole map or make clinical findings public.

Native Workbench plugin invocation and resource building follow the supported [Workbench plugin API](https://community.bistudio.com/wiki/Arma_Reforger:Workbench_Plugin) and installed generated ResourceManager API. The optional BCMM_BuildUITexturesPlugin is build tooling, not a gameplay dependency.
Accepted native owner pipeline: .checks/splint-network-20261026-172056-705, 198 server assertions/zero failures, three clients including JIP. The player has actual character replication ownership and starts naturally within reach. Each of seven anatomy handlers maps the correct region; open/selection-only status stays blank; only the checking player receives findings; stale panel views are rejected. Native bandage equip/animation/consumption and H/J/hold/reset tests pass. Final compact sizing/font adjustments subsequently passed Workbench and server resource validation; visual acceptance remains separate.

## Interface refinement

The native panel now uses one BCM button template with consistent typography, padding, hover/focus borders, muted gold selected states and disabled states. Its centred panel has a separate header and tab row. All frame offsets are explicit; the supplied anatomy is fitted at its original 0.6 aspect ratio, and all seven clickable regions move with it.

Treatments show six readable rows per page, with More Treatments and a page indicator for longer lists. Tab changes reset the page and scope displayed findings to the selected clinical topic. Clinical results remain cached per region/view, and opening/selecting anatomy still reveals no findings. Current patient highlighting, an inactive-state-disabled patient pager, contextual treatment cancellation and procedure progress are included.

Actual native review covered opening the panel, selecting the leg, clicking Check bleeding, seeing the private result and treatment pagination. The repeatable native UI smoke also verifies all seven labelled tab bounds and anatomy aspect ratio. A wider controller/accessibility/ultrawide play pass remains.
